# Evaluation scenarios: gs-cut

Use [evaluation policy](../README.md) and the current native skill. These are guidance, not executed results.

---

### Case 1: Sell-goal cuts respect Keep and actual polish evidence

**Fixture:** Sell goal; matching root and prototype briefs with built Climb floor/Tide rises, unbuilt Ghost/Boss rush; Keep tide; Out of scope excludes boss fights. Fresh check has unintended readable fail.

**Input:** $gs-cut

**Domain checks:**
- [ ] Observe both briefs, goals, features and evidence. Propose Boss rush first with the existing scope reason; never propose Tide rises. Polish row cites readable check and date.
- [ ] Name both briefs, polish file and affected stories before selection. Ask target and suggest a freeze 70% toward it, explicitly recorded and not enforced.
- [ ] Apply only selected cuts as [-] Out of scope with reason/date; use ISO target/freeze dates. A commit includes only agreed wrote paths and only when that commit instruction is explicit.

---

### Case 2: Noncommercial goal asks no dates

**Fixture:** As Case 1, hobby goal.

**Input:** $gs-cut

**Domain checks:**
- [ ] Do not ask, show or write target/freeze dates or rewrite project.goal. Selected planning and polish changes otherwise follow Case 1.

### Case 3: Unset goal is shown guessed, not saved

**Fixture:** As sell fixture with unset goal; original words say sell on Steam.

**Input:** $gs-cut

### Case 6: Stale evidence refresh changes no game files

**Fixture:** Case 1, config.js newer than check record.

**Input:** $gs-cut

**Domain checks:**
- [ ] Report the stale cause; run the authorized check once and record its actual outcome, without fixing game code. Re-read observations and cite only the refreshed evidence for polish.

---

### Case 7: Autonomous mode only writes polish

**Fixture:** Grown Web project, sell goal, autonomous, Ready stories traced to feature 2 and 4.

**Input:** $gs-cut

**Domain checks:**
- [ ] Run the authorized project smoke argv and turn actual failures into sourced polish rows. Write polish only; report cut/date proposals awaiting the person.
- [ ] No cuts, dates, commit or inferred acceptance. Unknown/unrun smoke stays unknown rather than inventing a fail or clean game.

---

### Case 8: Cut and restoration preserve stories and feature identity

**Fixture:** Case 7 collaborative; user selects feature 2 then later restores Ghost companion.

**Input:** $gs-cut

**Domain checks:**
- [ ] Cut moves the planning item Out of scope and Blocks its linked unfinished story with reason/date. Renumber remaining Brief MVP feature links coherently and name all changed stories before writes.
- [ ] Restore appends the feature with its selected built/unbuilt mark and correct link/status; keep completed-story evidence and do not delete story/code files. Commit only explicit round scope; no Git means Not committed.
- [ ] A cut implemented feature changes planning only; actual code removal is a separate choice. Restore only status/identity changes attributable to that cut, never erase unrelated blocker reasons.
