# Professional evaluation guidance

Use `$gs-skill-test` to inspect a native skill, apply a category rubric or exercise a
representative scenario in an isolated consumer. `$gs-skill-improve` diagnoses a real
failure and verifies the resulting change. [catalog.yaml](catalog.yaml) maps every
native skill/role to its scenario document. Use the [quality rubric](quality-rubric.md)
and [templates](templates/) for new cases.

The scenarios preserve upstream professional fixture inputs and domain assertions.
Host-specific frontmatter, tool aliases, forced delegation and blanket write approval
assertions are replaced by the current native contracts. The authoritative skill/role
procedure defines current arguments, verdicts, tier applicability and output schemas.
A source scenario is not evidence that any model or role passed it.

## Evaluation policy

- Resolve actual configuration and applicable prerequisites. Preserve full/standard/minimal domain requirements, review modes and strictest verdicts.
- Ask for unresolved creative or strategic decisions. Existing task authorization covers routine in-scope writes; an agent message or checkpoint supplies no new human authorization.
- Apply specialist knowledge with actual available tools. Delegation is optional and authorized. Label parent reviews and real participant outputs accurately; never invent independent sign-off.
- Use explicit native runtime commands, project-first engine references and linked SHA-256 review receipts. Historical fixture versions are inputs, not verified current engine facts.
- Record FORMAT, EXECUTED and NOT ASSESSED separately, including the actual host, command results, scope and missing inputs. A failed execution is a finding, not NOT ASSESSED or PASS.
- Synthetic scenarios validate framework behavior only. Real game balance, visuals, playtests, performance, engine builds, certification and deployment require consumer evidence.

When evaluating a case, record its input, relevant domain checks, actual result,
verdict, participants and remaining limitations in the consumer or PR review evidence.
Do not commit private game records or per-run evaluation logs into this framework.

[Source attribution](../../NOTICE.md) applies to the adapted scenario knowledge.
