# Codex Game Studios Constitution

## Core Principles

### I. Upstream professional baseline
Preserve MIT/Donchitos attribution and the complete professional lifecycle. Compare upstream changes with reviewed native content before reuse or adaptation. Reuse upstream implementations where compatible; retain only necessary host, authorization, safety and upgrade differences. Do not restore retired host entry points or regenerate reviewed content blindly.

### II. Consumer compatibility and ownership
Consumer packaging is limited to `.agents/skills/gs-*`, `.codex/agents/gs-*` and `.game-studio`. Preserve user files, reject unsafe paths and record ownership. Existing entry points, project configuration, instructions and recovery must remain usable during upgrades. Development tools never become consumer dependencies.

### III. Real authority and evidence
Inherit actual host tools and user authorization. Never ship model or permission pins, global configuration changes or hook trust bypasses. Parent-thread professional work is valid when identified accurately. Never fabricate independent participation, approval, screenshots, tests or game-quality evidence.

### IV. Reproducible verification
Use Python 3.11+ and requirements.txt. Test runtime behavior with targeted unittest checks. Validate content, links, evaluation catalog and release integrity with tools/validate.py. Rebuild reviewed payload hashes with tools/build_release.py and validate again. Scope tests to real new risks; scenarios remain evaluation guidance.

### V. Reviewable integration
Keep upstream commits as ancestors and provide a complete source-to-native map. Work on isolated branches; preserve existing work. Keep private games, paths and chat records out of the public framework. Obtain independent review before main integration, publishing or real consumer upgrades.

## Development boundaries
This repository distributes a framework, not a game. Temporary synthetic consumers may exercise installation and browser helpers; they do not establish game quality or all model behavior. Spec Kit is a maintainer tool only.

## Quality gates
Follow AGENTS.md and CONTRIBUTING.md. PRs separate FORMAT, EXECUTED and NOT ASSESSED evidence and describe compatibility, necessary host differences and remaining limits. Keep lasting usage knowledge in formal documentation; task execution evidence belongs in the PR and review conversation.

## Governance
This constitution records existing project rules; it does not replace user instructions or AGENTS.md. Amendments must explain the changed contract and compatibility. Feature plans must check every principle before implementation and after design. Preserve provenance when updating third-party tools.
