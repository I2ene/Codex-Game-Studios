# Game design workflow entry

Restore the project's existing context first. No general requirements-design skill is a prerequisite. Read [Codex compatibility](../../../codex/compatibility.md) and optional codex/context.json; follow its existing handoff contract instead of requiring a new PRD workbench.

Select and read the native SKILL.md for the current task, then execute its mapped source procedure. This router supplements the project's general requirements entry with the preserved professional game framework; it does not replace that entry or turn every design task into a generic PRD.

Preserve concepts, systems indexes, GDDs, reviews and specialist design outputs in the source design/ structure or the consuming project's explicit mapping. A workbench indexes those rule owners and maintains context, discussion and decisions without duplicating full game rules.

Known direction is not a complete core loop. Concept exploration may expose unknowns; system enumeration is not approval to create unrelated module tasks. Use actual data and observations for balance and playtest conclusions; missing inputs are not passes. Development runs and implementation remain handoffs to the code project.
