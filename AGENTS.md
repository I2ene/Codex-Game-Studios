# Codex Game Studios

This repository maintains the reusable studio framework. It is not a consuming game project. Keep game concepts, GDD content and project-specific context out of framework contributions; use isolated fixtures for behavioral checks.

## Codex design layer

Read codex/README.md and codex/compatibility.md for the adapted scope. Native entry and specialist skills live under .agents/skills; optional profiles live under .codex/agents. No external requirements-design skill is required.

The original .claude tree remains source reference material. It is not active Codex configuration. Preserve the upstream MIT license and declared source files. Do not execute original hooks or inline commands while reviewing or adapting their behavior.

Project context is an optional consuming-project contract through codex/context.json. Do not add a particular user's workspace paths, chosen game, workbench layout, asset storage or personal skill names to native framework instructions.

## Changes and validation

Keep the native inventory and source receipts in codex/manifest.json current. Validate native frontmatter/references, role TOML, preserved source hashes and installer behavior with the checks in codex/README.md. Use an actual behavioral scenario for substantive workflow changes and clearly separate runtime checks from game-design quality claims.

The current port covers design and design portions of entry/adoption/coordination. Developer implementations, hooks, engine setup, profiling, builds and releases need a separate adaptation. Do not advertise preserved original files as tested Codex features.

Use the human's explicit task authorization for Git or external publication; file maintenance alone does not authorize automatic commits, pushes or publication. Do not change global model, permission or trust configuration.
